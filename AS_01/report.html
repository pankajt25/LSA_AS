🧠 Technical Architecture & System Administration Reference

Viva Preparation

🔒 Sandboxing & Safety Constraint

Because useradd and groupadd modify live kernel/glibc databases (/etc/passwd, /etc/shadow, /etc/group), every test username is strictly validated against the regex ^lsatest_[a-zA-Z0-9_]+$. Any non-prefixed username is rejected immediately to protect human accounts.

🔑 Non-Interactive Password & PAM Expiry

Passwords are provisioned securely via echo "user:pass" | chpasswd without interactive prompts. Immediately after, passwd -e <user> (or chage -d 0) sets the last password change date to day 0 (Jan 1, 1970), forcing Linux PAM to demand a new password on first login.

📁 Home Directory Skeleton Seeding

The -m flag instructs useradd to initialize /home/<user> by copying base shell profiles (.bashrc, .profile, .bash_logout) from /etc/skel and assigns strict ownership (<user>:<department>) and directory permissions (0750 or 0700).

🏢 Departmental Group Association

The -g <dept> flag assigns the department as the user's Primary Group in /etc/passwd field 4 (GID). Department existence is queried first via getent group <dept> and created on-the-fly with groupadd if absent.

🔄 Two-Step Lifecycle & Teardown

Demonstrations follow a two-step pattern: bash run.sh provisions accounts and generates this live dashboard; bash cleanup.sh uses userdel -r and groupdel to completely restore the system to its pre-sprint state.

🌐 Multi-Platform Portability

The scripts dynamically detect WSL2, native Linux distributions, and macOS. When run on macOS, clear diagnostics explain that BSD/Darwin uses dscl instead of GNU/Linux useradd, avoiding cryptic failures.
