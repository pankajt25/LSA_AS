🔬 System Administration & Security Deep Dive

📚 'lastlog' vs. 'last' Architecture

Understanding the difference between the two standard Linux authentication logs:

  • lastlog reads /var/log/lastlog, a fixed-size sparse binary file indexed directly by UID (lseek(UID * sizeof(struct lastlog))). It retains ONLY the single latest login per UID and is never rotated. Accounts that have never logged in possess a zero-offset record displaying **Never logged in**.
  • last reads /var/log/wtmp, a sequential circular append log recording all login, logout, and reboot events. Because it grows continuously, it is rotated periodically (e.g. wtmp.1). If a user logged in 40 days ago and the log rotated 30 days ago, last shows no entries for that user.

🛡️ CIS Benchmark & Security Policy

Corporate compliance standards (CIS Linux Benchmark 5.4, NIST SP 800-53 AC-2):

  • Dormant Account Risk: Unmonitored inactive accounts represent severe security vulnerabilities for credential stuffing, privilege escalation, and persistent unauthorized access.
  • Standard Policy: Disabling or locking accounts inactive for 30 to 90 days.
  • Safe Remediation:
    • Lock password: sudo usermod -L <user>
    • Expire shadow account: sudo chage -E 0 <user>
    • Change shell: sudo usermod -s /usr/sbin/nologin <user>

⚙️ Multi-Tier Fallback & Sandboxing

Host compatibility and execution safety guarantees:

  • Modern Distro Fallback: On Ubuntu 24.04/26.04 minimal or WSL2 environments lacking legacy utmp binaries, the script seamlessly inspects live sessions via who, systemd user sessions via loginctl, and PAM authentication events via /var/log/auth.log.
  • Strict Read-Only Guarantee: This audit strictly inspects login timestamps. Zero user accounts are locked, modified, or deleted.
  • Confined Scope: All execution and log writing are strictly isolated inside the AS_02/ project workspace.
