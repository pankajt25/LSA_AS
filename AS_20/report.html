🧠 Linux Memory Accounting & Query Rationale
Engineering Notes

⚡ Why ps -eo ... --sort=-%mem

GNU ps accesses process memory structures directly from /proc/[pid]/statm and performs descending sorting in-memory before generating text output. The leading minus sign guarantees top consumers are output first. This eliminates external piping into sort, preventing pipeline race conditions, locale decimal bugs (dot vs comma), and SIGPIPE crashes.

💾 Why RSS Alongside %MEM

%MEM is a relative metric representing (RSS / Total RAM) * 100. On a 4 GB machine, 10% is ~400 MB; on a 128 GB node, 10% is ~12.8 GB! Resident Set Size (rss) provides the exact amount of physical hardware RAM currently held in pages by the process, excluding swapped-out data. Reporting both gives immediate proportional impact AND exact capacity consumption.

🌳 Lineage & Line of Ancestry

Querying ppid alongside pid allows instant identification of whether the high-memory workload is an independent service supervised by systemd (PPID 1), a scheduled cron job, a Docker container worker, or an unprivileged user process spawned from an interactive shell.

🛡️ Comm vs Full Command Args

Querying comm extracts the clean executable name from /proc/[pid]/comm rather than full command-line arguments (args). This ensures fixed-width tabular formatting remains stable across all viewports and immune to multi-line string wrapping distortion.
