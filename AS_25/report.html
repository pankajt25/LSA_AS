🧠 Architectural Reference & Network Mechanics

🔌 Bash /dev/tcp Virtual Redirection
Bash implements /dev/tcp/HOST/PORT as an internal parser abstraction rather than a physical filesystem node. When redirection occurs, Bash invokes libc getaddrinfo(), allocates a SOCK_STREAM socket, and executes connect() to complete the TCP 3-way handshake (SYN, SYN-ACK, ACK).
⚠️ Portability & Shell Constraints
/dev/tcp is a GNU Bash compile-time option (--enable-net-redirections). It is completely missing in POSIX /bin/sh, Debian dash, and BusyBox ash. Running scripts with sh results in "No such file or directory". This script strictly verifies Bash invocation and incorporates Netcat fallback.
🔄 TCP State & Rejection Differentiation
OPEN (Exit 0): Host replied with SYN-ACK; socket connected.
REFUSED (Exit 1): Host replied with TCP RST packet; port is actively closed.
TIMEOUT (Exit 124): No packet response within timeout limit; indicates firewall packet filtering (DROP) or unresponsive route.
🛡️ Resilient Netcat Fallback Engine
When /dev/tcp is disabled or forced via --nc, the script invokes OpenBSD netcat: nc -zv -w3 <host> <port>. The -z flag enables zero-I/O port scanning mode, ensuring no application payload is sent while testing socket reachability.
